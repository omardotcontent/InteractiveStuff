# 26.2 system overhaul

Historical baseline: the first overhaul was committed as `e3f9ffc` on `codex/26.2-system-overhaul`, based on the clean 26.2 commit `25ae15a`. The original `26.3` checkout and its three uncommitted port edits were preserved. The implementation is now shared by six version profiles. See [VERSION_PORTING.md](VERSION_PORTING.md) and [MULTIVERSION_VALIDATION.md](MULTIVERSION_VALIDATION.md) for the current layout and validation. The remaining details below record the original 26.2 overhaul.

## Changes and concrete cost reductions

| Previous behavior | New behavior |
| --- | --- |
| Every rendered item bound a model into all 15 active scripts, including two without item callbacks | Item filters select only relevant callbacks before binding or allocating the primary wrapper |
| Callback dispatch walked every active script | Immutable per-event callback indexes and cached per-item lists |
| Transforms, tint and even smoothing copied item stacks | Visual state is independent; only actual stack/component edits copy |
| Quaternions/tint maps allocated for every wrapper | Lazy allocation; direct quaternion rotation; cached shear matrix |
| Frame time depended on window backend timing units | Monotonic nanoseconds with a normalized 60Hz delta and 50ms cap |
| The physics library deduplicated by millisecond wall time | One integration per monotonic frame ID; wall time remains the wind source |
| Enchanting table built and bound up to 125 nearby block wrappers per render | A direct predicate scan memoized by tick and player block position |
| Repeated velocity getters recomputed trigonometry | Cache local velocity until source velocity or yaw changes |
| Copy-on-write collections used for client-thread scripts, debug text and extra models | Deterministic maps/lists and scoped render ownership |
| Native special layers and local transforms could disappear | Full native submission fast path and native special-layer fallback |
| Tint arrays were indexed by quad order | Material tint indexes map to explicit slots, including untinted geometry |
| Resolver seeds changed for every wrapper | Stable primary/extra slots for a given render |

The deterministic bundled-pack check reports:

| Held item | Old item-model bindings per render | New |
| --- | ---: | ---: |
| Stone | 15 | 0 |
| Chest | 15 | 1 |
| Redstone torch | 15 | 2 |

This is a measured reduction in callback/binding work, not an FPS percentage or a full allocation profile.

## Correctness improvements

- Same-duration Vyn waits are independent. Named cooldowns still deduplicate.
- Pause/resume keeps immutable heap entries; cancellation, callback replacement and clearing during callbacks are safe.
- Deferred callbacks carry an owner generation and cannot execute after reload. Errors disable the owning script once.
- Parsed script ASTs are reused across session resets and library imports.
- Circular/missing/invalid imports terminate instead of indefinitely retrying during a synchronous resource reload.
- Pack priority, lexical script order, persistent exclusions and full nested paths are deterministic.
- Player and living entity references refresh together; global world views remain live.
- Join, dimension change, resource reload and disconnect clear session work.
- Sound callbacks execute on the client thread; old-session queued sounds are discarded.
- Only key-down events outside menus dispatch key callbacks.
- Extra models inherit the actual main/off-hand context, are isolated across nested renders, and clean up after exceptions.
- Extra-only scripts keep vanilla's primary item visible.
- Native model layers, original tints, local transforms and special renderers remain intact.
- Matrix editing settings, sky/block light packing, tint fallback and visual copies are corrected.
- Camera yaw wraps across ±180 degrees. Negative player block coordinates floor correctly.
- Component data uses Minecraft's SNBT parser and registry-aware codecs, including nested values and quoted commas/colons. Model changes set the native component directly.
- Swing script events are independent of sound cooldown; hit sounds respect actual block targets and air/entity-capable materials.
- Config reload includes specialized note-block settings. Save refreshes material membership and writes through an atomic replacement.
- Unknown sound IDs fall back to stone audio. Null material/item/pitch entries are normalized.
- Mod Menu works without YACL by opening the config folder; custom pitch editing uses namespaced item IDs.
- Disabled debug mode avoids evaluating the bundled diagnostic getters.
- Custom model particle references resolve.
- The ordinary JAR includes Vyn and the actual license file. Metadata limits the build to 26.2 and requires Java 25; CI uses Java 25.

## Verification

Baseline: clean 26.2 `compileJava` passed before edits.

Automated core: 66 checks cover scheduler ordering/concurrency/reentrancy, pause/resume, timing, quad ranges, color multiplication, imports/cycles/exclusion, reload/deferred ownership, all 16 bundled scripts, callback filters, hand context, tint precedence, light packing, model copies, nested scopes and bounded geometry caching.

Actual client: Fabric client game tests ran with Minecraft 26.2, Fabric API 0.158.0+26.2, Java 25 and the existing OpenGL display/GPU. A fresh flat singleplayer world was created inside the test directory. The suite covers all 13 held-item features with an off-hand item, actual left-handed preference propagation, debug enabled/disabled, null-target note-block swings, nested SNBT and inventory isolation, config persistence/cache refresh, native special rendering, selected/complementary quad submissions, glint/light overrides, balanced pose stacks, concurrent waits, resource reload and disconnect.

Captured chest, leaves, water-bucket and left-handed frames were inspected. The test closes the world and client automatically. Development-account Realms/profile-key errors are unrelated to the mod; they do not fail these offline singleplayer tests.

Commands:

```bash
# Java 25 must be selected.
bash ./gradlew --offline --no-daemon build
bash ./gradlew --offline --no-daemon runClientGameTest
```

Client logs and screenshots are generated under `build/run/clientGameTest`. The test mod is excluded from the release JAR. The ordinary build can run without a display; the client suite is an explicit additional check.

## Practical limits

Generic tint/quad selection applies to baked item layers. Special renderer geometry is preserved through its native path; it needs renderer-specific support for custom color/selection. Opacity still follows Minecraft's material/render-type blending rules.

Script globals are per script environment; imported physics globals are per importing script. Hand identity is correct, but feature animation state is not automatically duplicated per hand. Pack authors can maintain separate hand state where needed.

Resource-pack models determine quad ordering. Split-model scripts still depend on the chosen model layout. Full animation/interaction tuning and every third-party animation/shader combination are outside the automated test's coverage.

Render-state and tint-array pooling is intentionally avoided: Minecraft retains submitted data until queue consumption. Reusing those objects mid-frame risks corrupting another item's draw.

The original overhaul did not change user saves or installed mod folders. The subsequent multi-version work publishes the requested version branches and commits; it creates no releases or pull requests.
