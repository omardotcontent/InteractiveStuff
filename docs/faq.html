Questions, answered

Everything people usually ask before installing — and a few things they ask after.

A client-side Fabric mod for Minecraft 1.21.10+ that adds immersive, interactive behaviours to items and blocks in first-person view: animated held items, reactive note blocks, sculk sensors, lanterns and much more.

No — and that distinction matters. InteractiveStuff is a first-person item interactions mod. It makes the things in your hand respond to the world; it doesn't rework how your character moves.

Currently 1.21.10, 1.21.11 and 26.2 on the Fabric loader.

No. It's client-side (Modrinth lists it as client-required, server-unsupported), so it works on any server. Other players just won't see your effects unless they install it too.

Fabric API is required. VynAPI, the scripting engine, is bundled inside the mod jar. Mod Menu and YACL are optional — together they give you an in-game config screen.

Install Mod Menu and YACL, then open Mods → InteractiveStuff → config button. You'll find Scripted Packs settings, Interactive Hits settings, and options to open the config directory or reload the configuration.

Three likely causes: the bundled resource pack is disabled or ordered wrong, you're in third person, or another pack is overriding the models. Check Options → Resource Packs first, and switch to first person.

If another pack imports InteractiveStuff's script libraries, the InteractiveStuff pack must sit below it in the selected list, otherwise the importing pack can't see the scripts it's asking for.

In your resource pack at assets/minecraft/scripts/*.vyn. Older guides say assets/interactivestuff/scripts/ — that path changed in the 0.7 snapshots.

Yes. Call excludeScript("interactivestuff:interactive_resourcepack", "sculk_sensors") from your own script, or just disable the bundled pack and ship your own selection.

Yes — InteractiveStuff works on the standard Fabric rendering pipeline. The one thing to be aware of is that scripts can set custom light values on held items, which some shader packs handle differently.

The bundled scripts check for holdmyitems and step aside automatically. For other animation mods, exclude the scripts that overlap with what they do.

Scripts run per rendered item per frame, so the cost scales with how much is happening. Keep your onItemUpdate guards tight (check the item name and gamemode before doing work) and it stays cheap.
